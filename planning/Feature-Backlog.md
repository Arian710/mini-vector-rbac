# Feature-Backlog & Ideen-Board

Oct 2, 2026 · @Arian

Sammelstelle für alles, was nicht in die aktuelle Version gehört, aber für v2/v3 vorgemerkt werden soll. Neue Ideen einfach unten ergänzen.

| Feature | Beschreibung | Status | Aufwand (grob) |
| --- | --- | --- | --- |
| PDF-Dokumente lesen können | Tickets/Dokumente nicht nur als Text, sondern direkt aus hochgeladenen PDFs/DOCX extrahieren und einbetten. Lange Dokumente werden automatisch in durchsuchbare Abschnitte (Chunks) zerlegt statt am Token-Limit zu scheitern. | Umgesetzt (v1) - inkl. DOCX | Mittel |
| Graph-Visualisierung (Obsidian-artig) | Dokumente als Knoten, automatische Verbindungen nach Cosine Similarity statt manueller Links; respektiert RBAC auch in der Graph-Ansicht | Umgesetzt (v1) | Groß |
| WhatsApp-Bot | Suche per WhatsApp-Nachricht stellen - praktisch fuer mobile Nutzer unterwegs, trifft nicht-technische Kunden (z.B. Makler) dort, wo sie ohnehin kommunizieren. Aufwand hoch wegen WhatsApp-Business-API-Verifizierung/Freigabeprozess. | Idee (ungeplant) | Groß |
| E-Mail/Slack-Suchanfragen | Suche per E-Mail oder Slack-Nachricht stellen statt die App zu oeffnen - nutzt die bestehende API. | Idee (ungeplant) | Mittel |
| Automatische Rollen-Vorschlaege | Beim Hinzufuegen eines Dokuments schlaegt die KI passende Rolle/Kategorie vor statt manueller Zuweisung - senkt die Huerde fuer Selfserve in Phase 3. | Umgesetzt (v1) - Hybrid Keywords+Embeddings | Mittel |
| Mehrsprachige Suche | Frage auf Deutsch stellen, Treffer auch in fremdsprachigen Dokumenten finden (Azure-Embeddings unterstuetzen das von Haus aus). | Idee (ungeplant) | Klein |
| Selfserve-Dokumenten-Upload | Kunden laden eigene Dokumente per Drag & Drop selbst hoch - Voraussetzung fuer den geplanten SaaS-Uebergang in Phase 3. | Umgesetzt (v1) | ☐ Mittel |
| OCR fuer Bild-only-PDFs (Azure Document Intelligence) | Fuer gescannte/fotografierte Expose-Seiten ohne Text-Ebene - Azure Document Intelligence statt lokalem Tesseract (vermeidet Windows-DLL-Probleme wie bei frueheren lokalen Installs). | Umgesetzt (v1) | Mittel |
| Individuelle Rollen-Verwaltung durch Management | Der Firmenchef/management definiert einmalig eigene Rollen im Dashboard (statt nur support/management), kann sie spaeter bearbeiten. Der automatische Rollenvorschlag beim Upload (role\_suggestion.py) muesste dafuer von binaer all/management auf eine tenant-spezifische Rollenliste erweitert werden - Keyword- und Embedding-Logik bleiben, aber Klassifikation wird mehrklassig statt binaer. Braucht: neue Tabelle fuer tenant-eigene Rollen, Admin-UI im Dashboard, Anpassung von allowed\_roles ueberall. | Umgesetzt (v1) | Groß |
| User-Verwaltung durch Management | Bewusst von der Rollen-Verwaltung getrennt (siehe oben): management legt neue User im Dashboard an und weist ihnen eine der selbst definierten Rollen zu, statt dass das weiterhin per seed\_data.py/direktem DB-Zugriff passieren muss. Braucht Passwort-Vergabe-Flow (Initial-Passwort vs. Einladungs-Mail - Mail-Versand existiert im Projekt noch nicht) und eine User-Liste/-Formular im Dashboard. Laut Fahrplan erst relevant, wenn ein echter Pilotkunde mehrere Mitarbeiter hat und Selbstverwaltung einfordert. | Idee (geplant) | Mittel-Groß |
| Migration auf Microsoft Entra External ID | Managed Identity Provider statt eigenem bcrypt+JWT - uebernimmt Breach-Password-Erkennung, Anomalie-Schutz, Session-/Refresh-Token-Rotation. Azure-nativ, RBAC/Tenant-Modell bleibt im Kern erhalten (role/tenant\_id als Custom Claims im Token). Aufwand eher Tage als Stunden (MSAL-Integration Frontend+Backend, Token-Validierung umstellen). Bewusst vertagt: aktuelle Loesung (bcrypt+JWT+Rate-Limiting, siehe auth.py) deckt die realistischen Risiken bei 1-2 Pilotkunden ab. Relevant, sobald SSO/Compliance von einem Kunden verlangt wird oder die Nutzerzahl deutlich waechst. | Idee (geplant) | Mittel |
| Branchen-Rollenvorlagen | Optionale Starthilfe auf der Rollen-Seite: Branche waehlen (Steuerberatung, Marketing-Agentur, Beratung, Immobilienmarketing), 3 vorgeschlagene Rollen mit Beschreibung uebernehmen/anpassen/ignorieren. Reine Frontend-Vorlagen, kein neuer Endpoint - nutzt den bestehenden POST /roles. | Umgesetzt (v1) | Klein |
